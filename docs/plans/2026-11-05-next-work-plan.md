# 下一阶段工作计划

## 目标

先稳定心跳 App 和音乐体验，再决定如何迁移上游大版本。当前 fork 基于小智 v2.0.4 / ESP-IDF 5.4.1；`78/xiaozhi-esp32/main` 已到 v2.5.3 / ESP-IDF 6.1，约有 485 个新增提交，直接合并会改动核心构建、应用和音频层。

## 顺序与验收

### 1. 心跳 App 生命周期与内存

- 审核进入/退出、定时器、动画回调和粒子对象的创建/销毁路径，确认退出后没有回调再访问已删除的 LVGL 对象。
- 在设备上重复打开、退出至少 20 次；稳定运行 10 分钟后记录 heap/PSRAM 基线和最低值。
- 通过条件：反复进出无崩溃；停止动画后 heap 回到稳定区间，没有持续单向下降。

### 2. 音乐与小智语音互斥

- 追踪音乐播放与语音 TTS/对话共用音频输出的状态切换，定义音乐暂停、语音占用、语音结束后的恢复策略。
- 保证停止或退出音乐 App 后 HTTP 流、解码任务和缓冲队列都被关闭。
- 通过条件：音乐播放期间触发语音时没有声音叠加；退出音乐后语音可立即正常播放。

### 3. 网易云搜索播放与电台卡顿

- 分别记录搜索结果、播放 URL 重定向、HTTP 状态/内容类型、首帧耗时、接收速率和解码 underrun，定位“搜得到但不能播”及电台卡顿发生在哪一层。
- 先复现并测量，再调整有限容量的预缓存/缓冲策略；避免无限缓存和阻塞 UI。
- 在稳定 Wi-Fi 与弱网条件下重复测试，记录歌曲和电台的连续播放结果及内存峰值。
- 通过条件：搜索出的可播放曲目能稳定输出音频；弱网卡顿有明确缓冲状态，不造成语音输出冲突或内存增长。

### 4. 上游大版本迁移评估

- 在独立迁移分支建立 v2.0.4 到 v2.5.3 的差异清单，先处理 ESP-IDF 6.1 和组件依赖变化，再迁移 Magai 板卡、App、音频和 MCP 改动。
- 对比 `main/CMakeLists.txt`、`main/application.cc`、`main/audio/`、`main/mcp_server.cc` 及板卡注册机制；不要在当前稳定分支做批量覆盖。
- 通过条件：magai-wifi 与 magai-ml307 都能构建，设备验收清单通过后再决定合并回主开发线。

## 验证基线

- 每次代码改动先跑 `git diff --check` 和针对性静态检查。
- 共享固件改动需构建 magai-wifi 与 magai-ml307。
- 目标板烧录后按 `docs/magai-apps-acceptance.md` 验证；串口日志记录重启原因、播放状态和 heap/PSRAM 数值。
